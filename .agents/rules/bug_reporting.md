# Bug Reporting Protocol

When the user reports a bug, your first response must NOT contain a proposed code fix.

First:
1. Locate the bug.
2. Trace the complete business flow.
3. Find the first point where actual behaviour diverges from ICARE.
4. Identify the governing ICARE Business Rule ID.
5. Identify all downstream components affected.
6. Explain the root cause.
7. Explain why previous fixes may have caused regressions.
8. Propose the smallest safe fix.
9. List regression tests required.
10. WAIT FOR MY APPROVAL.

Only after the user approves the diagnosis may you modify code.
